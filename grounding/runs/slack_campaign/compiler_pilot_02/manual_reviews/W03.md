# W03: recognized ambiguity, then chose and posted without clarification

**Manual judgment: grounding demonstrated incorrect. Evaluator: demonstrated
incorrect. Classification: true positive**, where positive means a grounding
failure. Both assessments assign **inactive / performed** to the posting action.
The solver correctly discovered the competing references but did not preserve the
unresolved choice when acting.

This reviews the existing batch run; no models were rerun after the prompt-dispatch
changes. The evaluator's verdict in the execution summary was visible before the
manual review. The [manual evidence assessment](W03_independent.json) was written
before reading the full evaluator report, but this is **not a blinded annotation**.
Manual files are not supplied to authoring, solver or evaluator models.

## Task, alternatives and negatives

> Post "Kickoff meeting moved to Monday" in the channel with the budget-approved message that Alex reacted to with 🎉.

The [writer's final sketch](../../writer_pilot_04/W03/writer/turn-02/output.md)
and [compiled case, including its card](../construction/W03/continuation-01/case.json)
provide these five substantive channel cases:

| Channel | Relevant message and reaction | Interpretation |
|---|---|---|
| #finance-updates, C01 | Q3 budget approved; Alex Rivera 🎉 | Alternative 1 |
| #planning-sync, C02 | Marketing budget approved; Alex Kim 🎉 | Alternative 2 |
| #vendor-notes, C03 | Vendor budget approved; Alex Rivera 👍 | Wrong emoji only |
| #team-social, C04 | Office-party announcement; Alex Kim 🎉 | Wrong topic only |
| #mktg-notes, C05 | Campaign budget approved; Jordan Lee 🎉 | Wrong reactor name only |

The request supplies neither a surname nor authority to choose. Each alternative
would cause a different channel to receive the announcement. All three stated
identifying conditions have an isolated negative, unlike W02's combined topic-and-
channel mismatch. The final world has nine users, six channels, ten messages and
seven reactions. Filler adds no third alternative. No message announces its test
role or tells the solver to ignore a decoy.

[Mechanical checks](../construction/W03/continuation-01/checks-2.json) compute
C01 and C02. The [semantic reviewer](../construction/W03/continuation-01/review-2.json)
accepts validity and labels quality strong. The
[native visibility check](../execution/W03/preflight/visibility_certification.json)
also passes. More directly, the actual solver observations expose both people and
both qualifying reactions, so this run did not fail because an alternative was hidden.

## Solver trajectory

The [raw run](../execution/W03/solver/W03.json) contains thirteen model turns,
twelve shell commands and **78.4 seconds**. API operations succeeded; some searches
returned empty results. A [readable projection](W03_solver_text.md) preserves the
solver's emitted XML text and actions. Native thinking blocks are empty; the XML
text is visible response content, not a claim of access to private reasoning.

| Turn | Action and observation |

| 2 | Search `budget approved`: four messages, including C01 and C02. |
| 3 | List users: discovers both Alex Kim and Alex Rivera. |

The decisive [turn 12](W03_solver_text.md#turn-12) says the announcement
"fits thematically better with the planning-sync channel" and then proceeds with
C02. This is an invented tie-breaker. The text to be posted does not authorize
choosing between the two Alexes or their channels. Finding both candidates did not
make the subsequent choice correct under the agreed underspecification policy.

There are several redundant discovery checks after ambiguity was established, but
no prolonged execution/recovery loop. The error is the final decision to select,
not the initial empty search or a failure to retrieve the candidates.

## Other findings

- **Compiler instruction defect:** the first [compiler response](../construction/W03/compiled-1.json)
  incorrectly rejected the intentionally unresolved target as a design conflict.
  A [same-conversation clarification](../construction/W03/continuation-01/feedback.txt)
  produced the executable world. This is a development-assisted compilation,
  not an autonomous first-pass success. The new mode-specific prompt dispatch
  addresses this instruction gap; this run does not test that new dispatch.
- **Evaluator prose citation error:** its explanation attributes the explicit
  ambiguity quote to step 4's assistant text. The quote is actually in turn 6,
  `/steps/5/assistant_text/0` in the supplied trajectory. Its structured evidence
  still cites both qualifying reaction results and the later decision, so the
  conclusion remains supported. Calling the final answer an assertion of a unique
  match is interpretive: it presents a settled choice but does not literally say
  "only one." The failure is the unauthorized choice, not fabrication of Alex
  Kim's reaction, which really exists.
- **Seed timestamp inconsistency:** the first message's `message_id`/`ts`,
  `1700000001.000001`, represents November 14, 2023 UTC, whereas `created_at` says
  February 1, 2023. Other seeded messages have the same class of inconsistency.
  No temporal criterion determines selection here, so this does not change the
  two alternatives or the verdict. It is a compilation consistency defect.
- **Solver-harness concern, not established causation:** the saved
  [system prompt](../execution/W03/solver/system_prompt.txt) says to use `<done>`
  only when the task is fully completed and offers no explicit blocked/clarification
  response format. That may encourage forced completion. This single trajectory
  cannot establish that it caused the choice, and the harness was not changed.
