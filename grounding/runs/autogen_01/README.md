# autogen_01: fact-discrimination tests generated and judged by Claude Code Sonnet agents

Sonnet agents in headless Claude Code, inside fixed scaffolding, write scenarios, read them cold, and judge an
agent's trials. The solver under test is Qwen `qwen3.8:27b` on Purdue GenAI Studio. The study compares the result
with the hand-built exemplars of fact_coverage_01 and fact_coverage_02.

## Start here
- [report.md](report.md): the results, the bars and what they mean.
- [plan.md](plan.md): the plan, fixed before the runs, with four dated amendments.
- [tables.md](tables.md): every table, generated by [kit/tables.py](kit/tables.py).
- [kit/README.md](kit/README.md): the pipeline, and how to run it on another domain.

## Layout
- `inputs/`: the manual domain input.
  - Per domain: `facts.json`, `replica.md`, `seed_ops.md` and `api.md`.
  - The brief files, and the scripts that derive them.
- `kit/`: the scaffolding (code), the agents' prompts, the writer's method notes and format, and the worked
  examples.
- `eval/`: my manual evaluation.
  - [validity.json](eval/validity.json): a verdict per accepted scenario and decoy.
  - [judge_review.json](eval/judge_review.json): my reading of every failing or void verdict.
  - [exemplar_outcomes.json](eval/exemplar_outcomes.json): the exemplars' recorded outcomes.
  - [autopsy.md](eval/autopsy.md): Arm R against the exemplars, fact by fact.
- `runs/`: the evidence. It is hidden from default ripgrep searches by `.ignore`.

| Run | What |
|---|---|
| `judge_dev_01`, `judge_dev_02`, `judge_test_01` | The judge against fact_coverage_02's manual labels (dev rounds, then the held-out split) |
| `judge_smoke` | Three smoke calls of the judge |
| `gen_dev_01`, `gen_dev_02`, `solve_dev_01` | Development: generation rounds and one end-to-end solver run |
| `reader_calibration_01` | The reader on the exemplars |
| `gen_arm_r`, `gen_arm_p`, `gen_arm_p_v2` | Generation: Arm R (the exemplars' facts), Arm P (new facts), and Arm P again with method v2 |
| `control` | The exemplars' 76 tests, prepared to run again on the same day |
| `solve_<arm>` | Qwen trials (`t1`..`t3/<test>/attempt-NN/`: solver transcript, state, diff) |
| `solve_<arm>_judged` | The judge's calls (`calls.jsonl`) and verdicts |
| `solve_<arm>.score.json` | The scored run, automated |

Each generated scenario folder (`gen_*/<id>/`) holds:
- every version of `scenario.json`;
- the pre-check and reader outputs per version;
- the writer's prompts, results and transcripts (`writer/`);
- `outcome.json`, with the history of findings;
- the accepted `case.json`.

Every agent call's usage is in its run's `calls.jsonl`. Calls that failed are kept as `*.failed.json`. First attempts
stopped by the session limit are kept as `<id>.attempt1-http429`.

## Regenerating the tables
From the repository root, with `GROUNDING_ENV` pointing at the Purdue key file:

```bash
L="python grounding/runs/fact_coverage_02/launch.py"
$L grounding.runs.autogen_01.kit.tables > grounding/runs/autogen_01/tables.md
$L grounding.runs.autogen_01.kit.autopsy > grounding/runs/autogen_01/eval/autopsy.md
python -m grounding.runs.autogen_01.kit.check_attachments   # the Linear attachments gap
python -m grounding.runs.autogen_01.kit.check_nested        # failing Linear paths, per run
```
