The only endpoint that modifies an existing message is `chat.update`, and its `ts` parameter is used solely to identify *which* message to update — there is no parameter to set a new posting timestamp. A Slack message's `ts` is fixed immutably at the time it is first posted, and the UI renders the visible time directly from it. The alternative (delete + repost) would assign the *current* timestamp (i.e., make it newer, not older) and would destroy the original message, its history, and any reactions — so it would not accomplish backdating either.
